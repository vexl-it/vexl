# Definitions index

The shared list of journey and aggregation definitions that the twelve files in `metrics/` reference. One line per definition here; the fields and the signal sites are specified in the metric file that owns the definition (column "Owner"). Names are the `name` values registered in `packages/analytics-definitions/registry.ts` (system.md section 5).

Rules that apply to every definition (system.md sections 2 and 3):

- Journeys with a lifetime over 7 days carry booleans and enums only and round `updatedDay` to the ISO week. Short journeys and aggregations may carry capped counters and duration buckets.
- The initial upload of every journey, and every upload of a club definition, is queued for the next app start.
- Country is stored on every row except club definitions (`storeCountry: false`); the dashboard suppresses small groups.
- Missing data is `unknown`, never churn. A journey that reaches its lifetime without a terminal step is reported as `unknown`.
- Core action, creation class and request class are defined once in `coreAction.ts` and used by every definition below. No UI surface is tracked; classes come from the offer.

Aggregation fields, in short:

- `weeklyActivity`: booleans `engaged`, `coreActive`; counters (cap 20) `offersCreatedMain`, `offersCreatedBoth`, `requestsSentMain`, `requestsSentClub`, `rerequests`, `importStartedOnboarding`, `importStartedSettings`, `importStartedReimport`, `importSuccess`, `importNothingNew`, `importZeroContacts`, `importPermissionDenied`, `importQuota`, `importError`, `gapD0To6`, `gapD7To29`, `gapD30To59`, `gapD60To89`, `gapGt90`.
- `monthlyActivity`: booleans `engaged`, `coreActive`, `coreMain`, `coreClub`; `initiations` (`CountBucket`).
- `marketplaceWeekly`: counters (cap 50) `marketplaceOpened`, `clubOffersOpened`; `firstLoadResult` (`offers`, `empty`, `notLoaded`), `visibleOffers` (`VisibleOffersBucket`, optional), `filteredEmptySeen`; offer demand roll-ups keyed by the offer's creation week (cap 20) `offersEnrolled`, `offersRequests0`, `offersRequests1`, `offersRequests2To5`, `offersRequests6Plus`, `offersDeletedBefore7d`, `offersPausedBefore7d`, `offersNotObserved`, `firstRequestLt1h`, `firstRequest1hTo24h`, `firstRequest1dTo3d`, `firstRequest3dTo7d`.
- `chatOutcomesWeekly`: counter (cap 50) `composerOpened`; request roll-ups keyed by the request's week (cap 20) `requestsEnrolled`, `requestsAccepted`, `requestsRejected`, `requestsHumanReply`, `requestsCancelledByMe`, `requestsNoAnswer`, `requestsUnknown`, and one `LatencyBucket` counter set each for accept, reject and human reply (`acceptLt1h` ... `replyGt3d`); snapshot buckets `openChats`, `inactiveChats30d` (`CountBucket`); counters `feedbackAfterD0`, `feedbackAfterD1`, `feedbackAfterD2To7`, `feedbackAfterD8To30`, `feedbackAfterGt30`.
- `clubActivityMonthly`: booleans `isClubMember`, `firstClubJoin`; counter (cap 10) `clubJoins`; `membership` (`MembershipBucket`), `clubsActedIn`, `clubOfferCreations`, `clubRequests` (`CountBucket`).
- `notificationsWeekly`: counters (cap 50) `received<Type>` and `tapped<Type>` per `NotificationType`, `displayed`; booleans `permissionEnabledToDisabled`, `permissionDisabledToEnabled`, `prefOptOut<Preference>`, `prefOptIn<Preference>` per notification preference (`offer`, `chat`, `marketplace`, `newOfferInMarketplace`, `newPhoneContacts`, `inactivityWarnings`, `marketing`).

Three weekly records instead of one: each stays well under the 64-key payload cap, each carries only one signal domain, and a device that never opens the marketplace or never sends a request simply has no `marketplaceWeekly` or `chatOutcomesWeekly` row that week.

## Shared enums

From `buckets.ts` (system.md section 5) plus the ones the metric files need:

- `DurationBucket`: `lt1m`, `1mTo10m`, `10mTo1h`, `1hTo1d`, `gt1d`.
- `DaysBucket`: `d0`, `d1`, `d2To7`, `d8To30`, `gt30`. Gives the 1, 7 and 30 day windows every cohort metric asks for.
- `CountBucket`: `0`, `1`, `2To5`, `6To10`, `gt10`.
- `LatencyBucket`: `lt1h`, `1hTo24h`, `1dTo3d`, `3dTo7d`. Request and first-request latency inside a 7-day window.
- `GapBucket`: `d0To6`, `d7To29`, `d30To59`, `d60To89`, `gt90`. Gaps between consecutive core actions.
- `VisibleOffersBucket`: `0`, `1To5`, `6To20`, `21To50`, `gt50`.
- `MembershipBucket`: `0`, `1`, `2To3`, `4Plus`.
- `NotificationType`: `chatMessage`, `newUser`, `newClubUser`, `clubAdmission`, `userInactivity`, `loginOnDifferentDevice`, `clubFlagged`, `clubExpired`, `newContent`, `product`, `newOffers`, `marketplaceReady`, `newContacts`, `tradeReminder`, `other`. Server task tags from `apps/notification-service/src/services/NotificationSocketMessaging/domain.ts` plus the client-scheduled ones from `apps/mobile/src/utils/notifications/notificationTypes.ts`. Campaign-like subset (enrols an `exposure` journey): `product`, `userInactivity`, `newOffers`, `marketplaceReady`, `newContacts`, `clubAdmission`, `newContent`.
- `PromptId`: `mpImportContacts`, `mpImportNewContacts`, `mpCreateOffer`, `mpEnableNotifications`, `mpEnableBackgroundRefresh`, `mpMissingProductCategories`, `mpBubbleAddMoreContacts`, `mpBubbleResetFilter`, `mpBubbleJoinVexlClubs`, `warning` (campaign = warning id), `dialogNotificationPermission`, `dialogDonation`, `dialogMarketplaceIntro`, `dialogNotesBoardIntro`, `dialogChatRating`. Inventory in `metrics/pop-ups-and-in-app-prompts.md`.

## Local state that never leaves the device

Markers (MMKV, immediate save, wiped on logout): `firstOpenAt`, `registeredAt`, `activatedAt`, `firstClubJoinedAt`, `lastCoreActionAt`, `lastReactivationAt`, `firstMainMarketplaceLoadAt`, `everJoinedClub`, last observed notification permission state. Only buckets derived from them are uploaded.

Local window records (MMKV, one per enrolled object, deleted when the window is evaluated):

- per owned offer: `createdAt`, `requestCount`, `firstRequestAt`, `deletedAt`, `pausedAt`, `lastInboxPullAt`. Rolled into `marketplaceWeekly` at the first app start after day 7.
- per sent request: `sentAt` (server accept time), `answer` (`accepted`, `rejected`, `humanReply`), `answeredAt`, `cancelledAt`, `lastInboxPullAt`. Rolled into `chatOutcomesWeekly` at the first app start after day 7.

In-memory flags (per process): "marketplace already counted this foreground session", "app has been backgrounded since the club join", "prompt already shown this session".

## Backend-only sources

Used as `backend` or `mixed` types; see `docs/backend_stats.md`: `USER_LOGGED_IN`, `COUNT_OF_ACTIVE_USERS` (and its by-country row), `OFFER_CREATED`, `TOTAL_*_OFFERS*`, `REQUEST_SENT`, `CHAT_CLOSED`, `USER_JOINED_CLUB_AND_IMPORTED_CONTACTS` or the `member_count_changes` table, `COUNT_OF_INACTIVE_USERS`, `USER_REACTIVATED`, `NOTIFICATION_SENT`, `INACTIVITY_NOTIFICATION_SENT`.
